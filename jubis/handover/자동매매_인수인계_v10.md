## 1. 일하는 방식 갱신 (v9의 1장에 추가·정정)

- **`del` 함정 (10/1 확인, 최중요):** v9의 "① `del` ② 다운로드 ③ `dir` ④ `copy`"를 사용자가 **한꺼번에 붙여넣으면 `del`이 방금 받은 파일을 지움**(브라우저 다운로드 목록에 "삭제됨"). → **`del`은 빼거나, 다운로드 *전에* 따로 실행.** 새 파일 이름이면 `del` 자체가 필요 없음. 권장 순서: ① 카드 다운로드 버튼(↓) 한 번 → ② `Esc` 후 `dir /b "%USERPROFILE%\Downloads\파일이름*"` → ③ `copy /Y ... C:\Users\PC_1M\` (노트북은 `C:\autotrade\`).
- 사용자가 파일 카드를 못 찾거나 **카드 이름만 눌러 미리보기만 열고 다운로드를 안 하는** 일이 반복됨 → "위로 스크롤하면 이름이 ○○인 카드, 오른쪽 다운로드 버튼(↓)" 식으로 구체적으로. 안 되면 **파일 없이 `python -c` 한 줄**로 실행(예: 설정만 바꾸는 실험). 단 그 방식은 최대낙폭 계산이 안 나옴.
- **사용자가 스크린샷을 cmd에 붙여넣어 이미지 경로가 입력되는 일**이 있었음 → "그 창에서 `Esc`, 입력은 명령만".
- **스크린샷에 KRX 아이디와 계좌번호(CANO)가 그대로 찍힘.** 아이디·비번·계좌번호는 가려 달라고 안내, AI는 번호를 따로 적지 않음. 계좌 비교는 "일치한다/안 한다"만 받기.
- **노트북 cmd:** 프롬프트 `C:\Users\user>`, 한글이 깨지면 `chcp 65001`. 파일 목록은 `dir /b C:\autotrade\*.py`. 노트북 폴더 JSON 보기: `type C:\autotrade\positions.json`, `type C:\autotrade\capital_state.json` (키 없음).
- **KRX `set`은 새 cmd 창을 열 때마다 다시 필요.** (두 줄 따로, 아이디·비번 채팅에 받지 않기)
- 사용자는 **폰으로 대화**할 때가 많음 → 폰에선 cmd를 못 돌리니 "PC/노트북 앞에서 할 일"로 모아서 안내. 응답은 한 화면 정도로 짧게, 표·짧은 목록 활용, 결론부터.
- 사용자의 "야 ~", "ㅇㅇ", "아니 근데" 같은 짧고 급한 말투 → 질문의 진짜 의도(예: "매일 매수하고 싶다", "종가베팅이 8시 아니냐")를 먼저 읽고 데이터로 답하되 단정하지 말기. 모르는 건 "제가 확인 못 함"이라고 말하기.
- **AI가 이번에 한 실수/정정 (반복 금지):**
  1. `del` 순서 (위).
  2. "돌파가 쉬는 날 종가베팅이 메운다"고 단정 → v16 엔진 코드상 **종가베팅도 같은 `market_ok`(지수 20일선·급락) 필터를 통과해야 함.** 노트북 설정(`CB_*`)에 따라 쉴 수 있음. 미확인.
  3. 후보 8 때 "멈춤선(-13%) 때문에 그대로 안 나왔을 것"이라 한 말은 부정확(리플레이가 같은 멈춤 로직을 이미 반영함).
  4. 계좌 불일치 때 모의투자 서버 가능성부터 의심 → 실제론 앱 조회 문제였음. 서버·계좌번호 확인 전에 단정하지 말 것.
  5. "눌림 일봉 10년"을 시험 전에 "새로 얻을 게 많다"는 식으로 기대를 준 면이 있음 → 결과는 대탈락. 새 후보를 소개할 때 "근거 없음"을 먼저 말하기.
- 사용자 성향 재확인: **더 벌고 싶어 새 조건을 계속 요청**(이번엔 삼성전자 단독, 눌림매매, 시간대 확장, 조건 완화, 종가베팅 접기, 한 계좌 100만 원 몰기). 매번 "규칙·기준을 먼저 고정 → 이미 본 1년은 참고용 → 판정은 새 기간"을 지켰고, 사용자는 결과를 받아들이고 다음으로 감. **"하 답답해 미치겠네 그냥 매일 매수했으면 좋겠다"**고 한 번 감정 표현 → 공감 + 대안(기록용 매일 돌리기/재미용 소액 계좌/실전 20회 기다리기) 제시, 사용자 선택 없음.

## 4. 새로 확인한 엔진·시장 사실

**종가베팅 청산 (PC `rule_engine_v16.py` 코드 기준. 노트북은 v15라 같은지 확인 필요)** — 검사 순서:
1. 익일 **09:15 이후 타임컷**: 가격 무관, **전량 매도** (코드에 "09:15" 하드코딩)
2. 손절 `CB_STOP = -1.5%` 이하 전량
3. (부분익절 후) 트레일링 `CB_TRAIL = 1.0%` (보유 중 최고가 대비)
4. 부분익절 `CB_TP1 = +1.5%`에서 `CB_TP1_RATIO = 0.5`
- **타임컷이 가장 먼저 검사돼서 나머지를 덮어씀.** 10/2 사례: 09:15에 -0.11%라 손절·익절 어디에도 안 걸리고 시간 때문에 판 뒤 주가가 +8.3%까지 오름.
- 사용자 질문 "가격 상황과 시간을 같이 보게 못 하냐" → 이미 손절·익절·트레일링은 가격 기준, 타임컷만 시간 기준. **제안한 청산 시험(미실행):** A 타임컷 10:30 / B 타임컷 15:15(손절·익절·트레일링은 그대로) / C 조건부(09:15에 0% 이상이면 15:15까지 연장, 손실이면 09:15 매도). 오늘 -0.11%라 **C는 오늘 결과를 못 바꿈**(A·B만 바꿈). **하루 결과로 안을 고르지 않기.** 기준은 현재 청산(09:15)을 같은 조건 1년 분봉 리플레이로 먼저 돌려 확보하고, A·B·C 중 **2개 이상**이 기준보다 좋을 때만 의미. 타임컷 시각이 코드에 박혀 있어 시험 스크립트가 실행 중에만 값을 바꿔 끼워야 함. 리플레이의 `trading_tick`이 종가베팅(정규장 15:25 주문 / 15:31 체결 확인)을 돌리는지, 현재 PC `my_keys`가 종가베팅을 꺼놨는지(기준 리플레이가 "종가베팅: 검사 없음"으로 나옴) **확인 필요**.
- 10년 종가베팅 검증(293회, +0.50%)의 청산 가정은 AI가 정확히 모름(다음날 시가/09:15 근처로 추정).
- 종가베팅 시장 필터: 코드(`run_candidates`, `run_closing_bet`)에서 `market_ok`를 통과해야 매수.

## 5. 사용자 결정·질문 정리

- **멈춤선(`DD_HALT_PCT` 기본 -13%)**: 사용자가 "더 늘려라/끄자" → 끈 버전(후보 10b) 결과 **멈춤선이 원인이 아니었고 꺼도 나빠짐.** AI 의견: 켜 두기. 종가베팅은 10년 낙폭 -15.0% > 멈춤선 -13%라 **넓히는 것(-18~20%) 검토 + "재개" 규칙을 미리 정하기**. **미결정.** (돈 결정은 사용자, AI는 투자 전문가 아님을 밝힘)
- **"종가베팅을 접을까?"** → 접을 근거 없음(10년 검증, 하락장 강함, 접으면 매수 날 더 줄어듦). 단 ① +0.50%가 비용(0.23%) 차감 후인지 확인 안 됨 ② 코스피 보유 대비 비교 미실시 ③ 멈춤선 < 10년 낙폭. 사용자가 "돌파 vs 종가베팅 뭐가 좋냐"도 물음 → 숫자는 돌파(1회 +1.57%, 낙폭 -8.2%)가 좋아 보이나 신뢰도는 종가베팅(10년·293회)이 높음. **둘 다 켜 두기.**
- **계좌 구조**: 두 계좌 각 50만 원. 사용자 제안 "한 계좌에 100만 원 + 그 계좌 방식 하나만 연구" → **연구 집중은 찬성, 돈을 몰아주는 건 보류**(실전 데이터 두 갈래가 더 값짐, 수수료 차이: 돌파 계좌는 우대/종가 계좌는 일반 위탁, 엔진은 0.015% 가정). 연구는 **종가베팅 하나(비용 반영 후 성과 + 코스피 보유 비교)**로 합의했고 사용자가 "그래 한번 부탁해" → **AI가 `closing_10y.py`를 올려 달라고 했으나 사용자가 아직 안 올림. 이 작업 미실행.** 만들 비교: 매매별 순수익률(수수료 0.015%+거래세 0.2% 반영), 같은 기간 코스피 보유, 투자한 하루당 수익·낙폭 대비 수익, 재투자 50% vs 100%.
- **재투자 50→100%, 금액 올리기**: 미결정(돌파 실전 20회 이후 비교하자는 제안 유지).

## 1. 사용자와 일하는 방식 (중요)

- **승주**. 한국어, 짧은 반말("ㅇㅇ", "ㄱ", "그래"). 오타 많음. **답변은 반드시 한국어.**
- **코딩·cmd 초보.** 한 단계씩, 결과 캡처 받고 다음 단계. 명령은 붙여넣는 한 줄. 표로 비교.
- 사용자가 "하나하나 다 해줘"를 원함 → 스크립트를 통째로 만들어 주고, 사용자는 받아서 실행만.
- **파일 전달 순서 (매번):** ① `del "%USERPROFILE%\Downloads\파일이름*"` ② 카드에서 **한 번만** 다운로드 ③ `dir /b "%USERPROFILE%\Downloads\파일이름*"`로 확인 ④ `copy /Y ... C:\Users\PC_1M\` 후 실행.
  - 사용자가 파일 받는 걸 자주 건너뜀("찾을 수 없습니다") → 카드 위치·다운로드 버튼(↓)을 구체적으로 안내.
  - PC 파일을 올려달라고 할 땐 `explorer /select,"C:\Users\PC_1M\파일이름"` → 파란 파일을 채팅에 끌어다 놓게. (이름 비슷한 `rule_engine_v16.py`를 잘못 올린 적 2번)
- **cmd 함정 (9/29~30 AI 실수):**
  - `findstr "a b"`는 띄어쓰기가 **"또는"**. 날짜+시각 검색 불가.
  - 로그·스크립트가 UTF-8이라 `findstr`로 **한글 줄을 찾거나 출력하면 깨지고 "쓰기 오류"** → 뒤의 `&&` 명령까지 멈춤. **확인은 `python -c`로.** 예: `python -c "print('X' in open('파일',encoding='utf-8').read())"`
  - 로그 보기: `python -c "L=[l.rstrip() for l in open('trade_log.txt',encoding='utf-8',errors='replace') if l.startswith('2026-09-29')];print('\n'.join(L[-40:]))"`
  - 입력칸에 글자가 남아 명령이 붙는 일(`.cachedel`) → "`Esc` 한 번 누르고 붙여넣기" 안내.

- 키·토큰은 "메모장에만".
- 9/29 한 번 욕설 → 담담히 한 번 말하고 넘어감. 이후 정상.
- **원칙: "주관 없이, 실제 데이터로."** 결과 보기 전에 규칙·숫자·기준을 **고정**하고, 결과 뒤엔 숫자 안 바꿈. 사용자는 더 벌고 싶어 계속 새 조건을 원함("매일 매매", "하락장 인버스", "1분봉 말고 5분봉"). → 실험은 해주되 매번 기준을 먼저 말하고, 이미 본 데이터로 재시험은 "참고용"으로만, 판정은 새 기간/안 쓴 데이터. 최종 결정은 사용자 존중.

# 8. ChatGPT와 새로 정리한 다음 전략 방향 (2026-09-30 밤)

## 핵심 목표

사용자는 **매일매일 매수 기회를 찾는 자동매매**를 원함.

단, 목표를 "매일 반드시 1회 매매"로 잡지 않는다.

목표는:

> **매일 전체 시장과 테마를 스캔하고, 그날 유효한 전략이 있으면 매매한다.**
> 조건이 없으면 0회도 허용한다.

현재 돌파 전략은 좋은 조건을 강하게 요구하기 때문에 4일 연속 매매가 없을 수 있다. 매매 횟수를 늘리기 위해 기존 돌파 조건을 무작정 완화하지 않고, **시장 상태별로 별도의 전략을 추가하는 방향**으로 간다.

## 현재 전략과 신규 전략의 역할

### A. 기존 돌파 전략

기존 전략은 유지한다.

- 상승장/강한 종목의 정석 돌파
- 20일 고가 돌파
- 거래량/거래대금
- 주도테마
- 시장 필터
- 기존 손절/익절/트레일링

기존 전략을 기준선으로 사용한다.

### B. 약세장 상대강도 전략 — 신규 후보 8의 핵심 후보

사용자가 원하는 "하락장에서도 올라가는 종목 찾기"를 인버스 대신 먼저 검증한다.

기본 개념:

> 종목 등락률 - 해당 시장 지수 등락률

예:
- 코스닥 -2%
- 종목 +3%
- 상대강도 = +5%p

이런 식으로 시장보다 강한 종목을 찾는다.

v16의 `signal_log.csv`에 이미 다음 데이터를 기록하도록 되어 있음:
- 시장구분
- 코스피등락률%
- 코스닥등락률%

후보 6 실험에서 30개 이상 데이터가 쌓이면 상대강도 상위/하위 절반의 다음 결과를 비교한다.

## C. 테마 + 신규돌파 전략

기존 후보 7 "테마 1등주 매수"는 탈락했으므로 그대로 사용하지 않는다.

기존 후보 7의 문제:
- 테마가 강해진 뒤 거래대금 1등주를 고르면 이미 많이 오른 종목을 추격할 가능성이 큼.
- 1년 리플레이 9회, 승률 44.4%, 1회 평균 -1.56%, 최종 445,559원으로 탈락.

신규 방향:

> **테마는 매수 신호가 아니라 후보군을 만드는 데 사용한다.**

예시 구조:

1. 강한 테마 발견
2. 해당 테마 종목 전체 스캔
3. 이미 과도하게 상승한 종목 제외
4. 아직 크게 오르지 않았지만 거래대금/거래량이 증가하는 종목 탐색
5. 직전 고점 또는 신규 고점 돌파
6. 상대강도 확인
7. 최종 진입

핵심은 "이미 폭등한 테마 1등주 추격"이 아니라 **"테마 안에서 이제 움직이기 시작하는 종목"**을 찾는 것.

## D. 횡보/혼조장 전략

시장 전체가 강하지 않더라도 특정 테마가 강하면 해당 테마 내부의 상대강도 + 신규돌파 후보를 탐색한다.

## E. 급락장

급락장에서는 무조건 인버스를 추가하지 않는다.

현재까지 인버스 A~F, 1분봉 8a/8b 등은 모두 탈락했다.

현재 데이터에서 확인된 결론:
- 20일선 아래 = 돌파매매를 쉬는 데는 유용
- 20일선 아래 = 앞으로 반드시 하락한다는 뜻은 아님
- 인버스 당일매매는 현재까지 근거 부족
- 하락장에서는 인버스보다 상대강도 롱 전략을 먼저 검증
- 시장 전체가 급락하고 상대적으로 강한 종목도 부족하면 매매하지 않는다.

## 중요한 원칙

### 1. 매매 횟수를 목표로 하지 않는다

"매일 1번"을 강제하지 않는다.

매매 횟수를 늘리기 위해 기존 조건을 무작정 풀면 현재까지의 실험처럼:
- 1회 평균 수익 감소
- 손절 증가
- 변동성 증가
가 발생할 수 있다.

### 2. 전략을 여러 개로 나눈다

하나의 거대한 AND 조건으로 만들지 않는다.

예:
- 상승장 → 기존 돌파
- 약한 상승/혼조 → 테마 + 신규돌파
- 하락장 → 상대강도 + 신규돌파
- 극단적 급락 → 쉬기

### 3. 추격매수 방지

특히 시가 대비 과도하게 오른 종목은 주의한다.

현재 후보 1:
- `BO_MAX_FROM_OPEN = 10.0`

이 숫자는 기존 실험계획대로 고정하고 새 기간에서 판정한다.

### 4. 데이터가 먼저

새 전략은 반드시 별도 후보로 만들어:
- 기준 규칙 고정
- 과거 데이터에서 시험
- 이미 본 기간은 참고용
- 새 기간에서 최종 판정
- 결과를 보고 숫자를 바꾸지 않음

### 5. 신규 후보 8은 기존 봇을 바로 교체하지 않는다

먼저 백테스트/리플레이로 검증한다.

검증할 핵심 지표:
- 매매 횟수
- 승률
- 1회 평균 수익률
- 최종 금액
- 최대낙폭
- 손절 비율
- 시장 상태별 성과
- 특히 하락장에서의 성과

## 사용자 목표와 전략 설계의 차이

사용자는:
> "상승장이든 하락장이든 그날 올라가는 테마/종목은 있고, 인버스까지 포함해 매일 돈 벌 기회를 찾고 싶다."

현재 데이터가 보여주는 것은:
> "매매 기회가 항상 존재한다고 가정하지 말고, 어떤 시장에서도 상대적으로 강한 종목이 있는지를 데이터로 확인해야 한다."

따라서 시스템 목표를:

**매일 매매**
→ **매일 탐색**
→ **시장별 적합한 전략 선택**
→ **조건이 맞을 때만 매매**

로 정의한다.
