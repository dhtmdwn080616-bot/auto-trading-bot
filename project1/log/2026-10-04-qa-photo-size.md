# QA: photo-size 배포 전 검수 (2026-10-04, p1-qa)

결론: 배포 차단급 결함은 없음. 단위 12/12, E2E 8/8(+fetch 차단, 외부 요청 0건) 통과. 단 [대표 확정] 자리표시자와 규격 1차 출처 확인 전에는 공개 배포 비권장.

## 수정한 것
1. 용량 표시 불일치: 목표는 1KB=1000바이트인데 결과 표시는 /1024라 "500KB 이하"인데 488.3KB로 보임 -> formatKB를 1000 기준으로 통일 (core.js, 테스트 추가).
2. EXIF 방향 경고 추가: core.js parseExifOrientation(JPEG 앞 128KB 로컬 파싱) + index.html #orient-note + css .status.warn. 방향값 2~8이면 "자르기 화면·미리보기 방향을 확인하라, 다르면 사진 앱에서 바로잡아 재업로드" 노출. 안내 문구 hint/guide(6절)에도 추가. 테스트 추가. 실측: 방향 6 JPG를 Chromium에서 열면 200x400으로 회전 반영 + 경고 표시 확인.
3. 상태 경합 버그: (a) 입력값이 잘못된 순간 진행 중이던 변환이 끝나 다운로드 버튼이 다시 켜질 수 있었음 -> readSpec 오류 시 timer 취소·token 무효화. (b) 새 사진 로드 직후 250ms 동안 이전 사진 결과가 다운로드 가능했음 -> 로드 시 다운로드 비활성·token 무효화. (c) 사진을 연달아 고르면 늦게 끝난 이전 디코딩이 덮어쓸 수 있었음 -> loadToken 도입.
4. ObjectURL: 새 URL 생성 후 이전 URL revoke 순서로 변경(간극 제거). decodeWithImg는 기존대로 revoke 정상.
5. 불러오기 실패 문구: 큰 사진 실패도 "형식 문제"로만 안내하던 것을 "형식 또는 너무 큼"으로 수정.
6. 표시광고: 프리셋 라벨 3개에 "참고값" 추가(공식 규격 오인 방지), guide 문구 동기화. guide 4절 "가장 높은 품질을 찾습니다"는 7회 탐색 근사라 "가능한 한 높은 품질(최댓값 보장 아님)"로 완화.
7. privacy: 다운로드한 파일은 사용자 기기에 남는다는 점 추가.

## 점검 결과(문제 없음, 코드로 확인)
- privacy 일치: grep으로 localStorage/sessionStorage/cookie/indexedDB/fetch/XHR/beacon/WebSocket/인라인 style/외부 URL 없음(유일한 외부 URL은 guide의 passport.go.kr 링크). 모든 페이지 meta CSP default-src 'none', connect-src 'none', 외부 리소스 없음. E2E에서 fetch 차단과 localhost 외 요청 0건 확인. 사진은 File->ImageBitmap->canvas->Blob(blob URL)로만 처리.
- 크롭/줌/clamp/이분탐색: 코드 리뷰와 단위 테스트상 이상 없음(ok=true는 항상 실측 크기 <= 목표). 고정 px 프리셋은 용량 못 맞추면 크기를 몰래 줄이지 않고 오류 표시, '용량만 줄이기'만 크기를 줄이고 고지.
- 규격 수치 계산: 3.5cm/2.54*300=413, 4.5cm->531, 3cm->354, 4cm->472 산술 맞음.
- 접근성: 라벨 연결, 건너뛰기 링크, 포커스 링, 44px 터치 타깃, 키보드 조작(방향키/+/-/0), aria-live, 다크모드 대비 색 설정 확인(대비비율 실측은 안 함). 모바일: viewport, touch-action:none, 1열 레이아웃.
- 비밀·개인정보: 키/토큰/개인 연락처 없음. 테스트 이미지는 저장소에 없음.

## 대표 판단 필요 (고치지 않음)
1. [대표 확정] 자리표시자 5곳/3개 파일: privacy.html 시행일, 호스팅 서비스·접속기록 정책, 운영자, 문의 방법(총 4항목) / about.html 운영자·문의 방법(1곳). 문의 수단을 이메일 등으로 정하면 개인정보 수집이 생기므로 "수집하는 개인정보 없음" 문구와 개인정보 보호법상 처리방침 요건을 다시 검토해야 함(법률 확인 못 함).
2. 규격 출처: "공개된 2차 자료"만 표기되고 구체 출처·확인일이 없음. 여권 413x531/500KB와 온라인 허용범위를 외교부(passport.go.kr 등) 1차 자료로 확인한 뒤 출처·확인일 표기 권장. 확인 전엔 지금처럼 "참고용" 유지.
3. 프리셋 중복: '여권 사진'과 '증명사진 3.5x4.5'가 같은 px. 합칠지 결정. 3x4/증명 500KB는 임의 기본값(문구에 명시됨) - 유지 여부.
4. 상호/도메인/브랜드명에 "여권" "공식" 오인 소지 여부(현재 "공식" 단어는 외교부 링크 설명 "공식 안내 예"에만 있음. 이 링크는 외부 접속 금지로 유효성 미확인).
5. 배포: tests/ 및 README.md는 배포 제외, 호스팅 HTTP 헤더로 CSP(+ frame-ancestors, X-Content-Type-Options) 추가 권장. meta CSP는 frame-ancestors 미지원.
6. 접근성 개선 후보: 자르기 canvas가 role="img"+키보드 조작이라 스크린리더에 부정확(role=application 또는 별도 컨트롤 검토). 슬라이더 값 텍스트 없음.
7. 큰 사진: 수천만 화소 사진은 브라우저/모바일 메모리에서 실패할 수 있음(이번엔 문구만 개선). 해상도 상한·사전 축소를 둘지.
8. 방향 경고는 EXIF 방향값이 있으면 항상 표시(브라우저가 이미 반영한 경우에도). 정밀 판별은 불가해 보수적으로 둠. 문구 톤 확인.
