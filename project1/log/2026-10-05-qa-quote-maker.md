# QA: quote-maker(견적서·거래명세서 생성기) 배포 전 검수 (2026-10-05, p1-qa)

결론: 차단급 결함 없음. 단위 13/13, E2E 36개 항목 전부 통과(수정 후 재실행). 아래 "대표 판단 필요"의 세무 문구 확인(세무사/국세청) 전에는 "참고용 양식 도구" 포지션을 유지할 것. 배포 시 tests/, README.md 제외.

## 수정한 것
1. 작성일을 비우면 인쇄물에 "작성일: 년 월 일"로 빈칸이 접혀 보이던 것(HTML 공백 병합)을 nbsp로 고쳐 기입 칸이 남게 함 (js/app.js). 실측 확인.
2. JSON 내려받기 주의 강화: privacy.html에 "사업자등록번호·상호·대표자·주소·연락처 등 공급자·공급받는자 정보가 암호화 없이 그대로 들어 있음, 공유·공용 기기 주의" 추가. index.html, guide.html 문구를 "사업자 정보"에서 "사업자·거래처 정보"로 맞춤(거래처 대표자·연락처는 타인 정보일 수 있음).

## 점검 결과: 문제 없음 (근거)
- (1) 표시광고: index 상단 notice(눈에 띄는 박스), 모든 페이지 푸터, 인쇄물 하단에 "양식 작성 보조 / 세금계산서 아님 / 법적 효력·세무 신고 인정 보장 안 함" 고지. "세금계산서 발급", "신고용", "공식" 류 단정 표현 없음. 면세·사업자번호 진위는 판단하지 않는다고 명시.
- (2) 계산(node 직접 실행, BigInt 정수 연산): 한글 금액 0=영, 10=일십, 100=일백, 10000=일만, 100000000=일억, 1234567890=일십이억삼천사백오십육만칠천팔백구십, 24자리 최대값 정상. 별도 5원->세 1(0.5 올림), 1원->0, 포함 100000->공급 90909/세 9091, 포함 10->9/1, 포함 5->5/0, 면세, 0원, 수량 1.5x333=500, 0.001x500=1, 0.0005는 오류(소수 3자리 한도), 음수·지수표기·전각숫자·"1." 은 오류 처리, 쉼표 입력 허용. 품목 100행 최대 입력 합계도 24자리 이내로 한글 표기 가능. 인쇄 레이아웃도 21자리 금액에서 넘침 없음(PDF 확인).
- (3) privacy 일치: localStorage/sessionStorage/cookie/indexedDB/fetch/XHR/beacon/WebSocket/innerHTML/외부 URL/인라인 style grep 결과 없음. 전 페이지 CSP default-src 'none', connect-src 'none'. E2E에서 외부 요청 0건, fetch 차단, 쿠키·저장소 미사용 확인. 시행일, 운영자(프로젝트원스튜디오), 문의(dhtmdwnproject@gmail.com), GitHub Pages 안내는 photo-size와 문구까지 동일.
- (4) XSS: 사용자 값은 textContent/value로만 출력. JSON 불러오기: app/version 검사, 알 수 없는 필드 폐기, 길이 제한, 품목 100개·1MB 제한, null/배열/비문자 값 거부(오류 메시지 표시), 날짜 검증. 비고에 `<img onerror>` 넣어도 문자열로 처리(E2E+node). 대량 40행 인쇄 PDF, 모바일 가로 넘침 0 확인.
- (5) 접근성: label 연결, 건너뛰기 링크, 포커스 링, 44px 타깃, aria-live, aria-invalid, 다크모드, 인쇄 미리보기 스크롤 영역 키보드 포커스. 대비비율 수치는 미측정.
- (6) guide: 외부 링크 0개(국세청·홈택스는 이름만 언급, URL 없음). 사실 단정은 "일반적으로 쓰이는", "~할 수 있습니다"로 완화돼 있음.
- (7) [대표 확정] 등 자리표시자 없음(HTML/JS grep). 미사용 CSS `.placeholder`(css/style.css 154행)만 잔존, 무해.

## 대표 판단 필요 (고치지 않음)
1. 세무 문구 확인: guide "세금계산서는 부가가치세법에 따라 발급하는 별도의 문서", "견적서·거래명세서 일반 용례", 반올림 규칙(원 미만 반올림)이 실무 표준과 맞는지 세무사 1회 확인 권장. 현재 화면이 "거래처와 1원 차이 가능"을 고지하고 있어 위험은 낮으나 1차 출처 미확인.
2. 면세 선택지: 영세율·간이과세자·과세/면세 혼합 거래는 이 도구가 구분하지 않음(고지는 있음). 지금 범위로 갈지, 지원 안 한다고 더 눈에 띄게 쓸지.
3. 한글 금액 "일금 ○○원정"과 1을 '일'로 쓰는 표기는 관행으로 안내했으나 근거 출처 없음. 유지 여부.
4. 인쇄물 하단의 "이 문서는 세금계산서가 아닙니다" 문구는 거래처에 보내는 문서에 찍힘. 사용자가 싫어할 수 있으나 오인 방지를 위해 유지 권장. 제거 옵션을 둘지.
5. 개인정보: 문의 메일 "처리 후 지체 없이 삭제"를 실제로 이행해야 함(STATE.md에 이미 기재). 문의 메일 수신 시점의 개인정보 보호법 의무는 법률 확인 못 함.
6. 배포: tests/, README.md 제외. 호스팅 헤더로 CSP+frame-ancestors+X-Content-Type-Options 추가 불가(GitHub Pages는 헤더 설정 불가) -> meta CSP만 적용되며 클릭재킹(frame-ancestors) 방어는 안 됨. 허용 가능한지.
7. 기능 한계 공지 여부: 할인(음수) 행, 직인 이미지, 절사·품목별 세액 옵션 없음(README 부채). 사용자 요구가 많으면 추가.
8. 브라우저 자동완성(autocomplete="organization" 등)은 브라우저가 별도로 값을 저장할 수 있음. 이는 사이트 저장이 아니라 privacy 문구와 모순은 아니나, 공용 PC 주의 문구를 넣을지.

## 확인 못 한 것
- 한국 세법(부가가치세법 반올림·세액 계산 규정, 세금계산서·거래명세서 보관/기재 요건), 표시광고법, 개인정보 보호법 조항 적합성: 법률·세무 검토 아님. 확실하지 않음.
- 실제 iOS/Android/Safari/Firefox 인쇄·PDF 저장·파일 불러오기, 모바일 파일 다운로드: 실기기 미검증(headless Chromium만).
- 한글(HWP)/엑셀 등으로 옮겨 쓸 때의 서식, 실제 프린터 출력 여백.
- WCAG 대비비율 수치와 스크린리더 실사용 테스트 미실시.
- 외부 접속 금지로 홈택스·국세청 안내 내용 대조 불가(가이드에 URL은 없음).
- E2E 실행 중 Chromium 자체가 구글 도메인으로 접속 시도(프록시가 거절). 페이지 요청은 0건이므로 도구와 무관한 브라우저 백그라운드 트래픽으로 판단.
- git 커밋 안 함. 변경 파일: js/app.js, index.html, guide.html, privacy.html. (quote-maker 폴더 자체가 git 미추적 상태)
