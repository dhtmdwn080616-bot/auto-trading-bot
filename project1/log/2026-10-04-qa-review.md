## 2. 대표 판단 필요 (고치지 않음)
A. 실제 위험도 높은 것
1. 저장소가 public이다(gh API로 private=false 확인). project1 내부 문서(가격 가정, 전략, 로그), 거래 봇 코드(bot.py), 실행 파일(actionlint tarball)이 모두 공개 상태다. Pages는 portfolio/만 배포하지만 나머지도 누구나 본다. 고객이 생기면 고객 정보가 섞이면 안 된다. 권고: 포트폴리오 전용 저장소 분리(PAGES-SETUP 대안 B) 또는 이 저장소 private 전환.
2. 시안 링크(reply-templates 5번 "시안 링크")를 GitHub Pages로 주면 고객 시안(상호·가격·영업정보)이 공개 URL에 노출된다. 시안 비공개 공유 방식을 정해야 한다(예: 파일 전달, 비밀 URL이 아닌 별도 수단). 납품 전 공개 여부도 고객 동의 필요.
3. AI 활용 고지의 정직성: 크몽 문구는 "운영자가 확인·검수 후 납품"이라고 쓴다. 대표가 실제로 모든 납품물을 확인할 수 있을 때만 유지할 것. 또한 고객 문의 답변 초안·QA 점검도 AI가 하는데 고지는 "제작"만 다룬다. 고객이 AI 상대로 대화한다고 오해할 수 있으면 "문의 응대에도 AI를 보조로 씁니다"를 추가할지 결정. 프로필의 "저는...운영자인 제가 검수"는 대표 본인 1인 사실과 맞는지 확인.
4. 고객 자료가 Claude(해외 AI 서비스)에 입력되는 점: 질문지에 고지문을 넣었지만(수정 2), 개인정보 국외 이전·위탁에 해당하는지, 별도 동의/처리방침이 필요한지는 법무 확인이 필요하다. 상품 A·B·2번 A 본문(제작 방식 섹션)에도 같은 문장을 넣을지 대표가 결정.
5. 상품 A(79,000원)에 "문의 폼 포함"으로 적었는데 FAQ는 "개인정보처리방침은 B 이상 또는 별도 협의"라고 한다. 이름·연락처를 받는 폼을 A에 넣으면 동의 문구와 처리방침이 필요하고, 정적 사이트라 폼 데이터를 받을 곳(저장·전달 방식)도 정해지지 않았다. 권고: A는 "전화·카카오톡·메일 버튼"으로 한정하고 폼은 B로. README(A에 문의 폼 포함)와 같이 수정해야 하므로 대표 결정 후 반영.
6. 보관 기간(`{{보관 기간}}`): 대표가 정해 질문지 붙여넣기 전에 채울 것. 값이 비어 있으면 그대로 발송되지 않게 주의(체크리스트 상 `{{ }}` 확인 단계 있음).

B. 일반 판단
7. 가격 일관성: 양사 listing과 README 범위는 일치한다(1번 A 79,000원 vs README 6~10만원대, B 300,000원 vs 30만원대, 수정 A1/B2/C3, 2번 A 80,000/150,000원 vs 5만~15만원대). 단 모두 근거 통계 없는 제안값이다. 1번 A 수정 1회, 2번 A 수정 1회/2회는 README에 규정이 없는 가정치다.
8. 크몽 listing 안의 `[대표 확정]`, `[가정]` 표기는 붙여넣기 블록 안 표에 들어 있다(상단 박스는 "붙여넣지 않는다"고 적었음). 등록 시 지워지지 않으면 공개 문구에 남는다. 체크리스트에 미리보기 확인 항목이 있으나 대표가 인지할 것.
9. 병·의원 대상 상품(B): "치료 효과 단정·환자 후기 게시 금지" 문구는 안전한 방향이다. 다만 의료광고 사전심의 대상 여부, 의료기관이 홈페이지를 제작사에 맡길 때의 책임 구조는 확인하지 못했다. 병·의원 주문 시 의뢰인이 심의/책임을 확인하도록 계속 안내하고, 병원 주문은 받기 전 대표가 전문가(변호사·의료광고 심의 기관)에 확인 권고.
10. 학원 샘플의 "소수 정예", "무료 레벨테스트", 카페 샘플의 "직접 로스팅", "스페셜티커피"는 가상 업체 예시지만 고객이 그대로 복사하면 사실과 다른 표시가 될 수 있다. 질문지·납품 템플릿에 "사실 확인은 의뢰인" 안내는 있다. 샘플 문구를 더 중립적으로 바꿀지 판단. 학원법상 광고·게시 의무(수강료 등) 확인 못함.
11. 샘플 3종에 noindex 메타가 없다. 가상 업체명이 검색에 노출되면 실제 동명 업체와 혼동될 수 있다. 업체명(모닝브루, 새봄 수학학원, 맑은숨 이비인후과)이 실제 상호와 겹치는지 상표/상호 검색은 하지 않았다.
12. 크몽 메시지에 외부 링크(github.io 샘플 링크)를 넣어도 되는지, 포트폴리오에 샘플 캡처만 허용되는지 약관을 확인하지 못했다. 후기 요청 문구(reply-templates 7번)가 약관의 후기 유도 금지에 걸리는지도 확인 못함(대가·평점 요청은 이미 금지로 적혀 있음).
13. GitHub Actions를 태그(@v4 등)로 참조 중이다. 보안 강화를 원하면 커밋 SHA 고정. 현재는 GitHub 제작 액션만 사용하고 시크릿 없음, push to main과 수동 실행만 트리거라 위험은 낮다.
14. 2번 A: 카카오 AI 상담 기능과 중복 위험은 이미 문서에 기재됨(10-14 확인 후 등록). AI 응답 고지의 법적 의무(인공지능 관련 법)는 확인하지 못했다. 문서는 "법규상 필요할 수 있어 안내문 제공"으로 표현해 단정하지 않는다. 등록 전 법무 확인 권고.
