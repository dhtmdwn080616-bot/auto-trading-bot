# 크몽 등록 체크리스트 (대표용, 1번 웹/랜딩 상품 A·B)

크몽 화면 구성은 제가 직접 확인하지 못했습니다(사이트 접근 불가). 화면 항목명이 아래와 다르면 가장 가까운 칸에 넣고, 막히면 화면을 알려 주세요. 수수료와 등록 절차는 판매자센터에서 직접 확인하고 리서치 수치(16.4% + 3.3% + 부가세)와 다르면 알려 주세요.
일정: 10-09 한글날 휴일, 검토 3~5영업일 [사실, 2차 자료] → 10-10(토) 등록 시 영업일 기준 10-14~10-16 예상 (10-12 월요일부터 3~5영업일 계산. ROADMAP의 요일 표기와 다를 수 있으니 달력으로 확인).

## 0. 시작 전 결정 (10분)
- [ ] `kmong-product-A.md` 상단 "대표 확정 필요" 읽기. 가격 제안값 확인: A 79,000원 / B 300,000원 (README 가정 구간 안의 제안값, 근거 통계 없음). 바꾸면 해당 파일의 숫자를 교체
- [ ] A의 수정 횟수 1회(가정) 확정
- [ ] `profile.md` 의 `{{닉네임}}`, `{{연락 가능 시간}}` 정하기. 지킬 수 있는 시간만 쓰기
- [ ] 프로필 사진 결정
- [ ] 사업자등록 없이 시작하는지 확인 (초기 2주는 미등록 개인, 반복 매출 시 세무사 상담 권장)

## 1. 크몽 가입과 인증
- [ ] 크몽 접속 → 전문가(판매자) 가입 → 개인 전문가 선택
- [ ] 본인인증 진행 (대표 본인이 직접)
- [ ] 판매자센터에서 현재 수수료, 등록 절차, 출금 조건 확인 (다르면 에이전트에 전달)

## 2. 프로필 등록
- [ ] 전문가 프로필 편집 열기
- [ ] 이름/닉네임 칸: 정한 닉네임
- [ ] 한 줄 소개 칸: `profile.md` 의 "한 줄 소개" 블록
- [ ] 소개(본문) 칸: `profile.md` 의 "소개 (본문)" 블록 (`{{ }}` 채운 후)
- [ ] AI 활용 안내 칸이 있으면 `profile.md` 마지막 블록
- [ ] 프로필 사진 업로드
- [ ] 경력/학력/자격/수상 칸: 실제로 있는 것만 입력. 없으면 비워 두기 (가짜 입력 금지)

## 3. 포트폴리오 준비 (등록 전)
- [ ] GitHub Pages 공개 확인 (ROADMAP "즉시" 항목). 공개 페이지(`portfolio/` 배포본)의 index와 샘플 3종(academy, cafe, clinic) 링크 확인. 이 공개 저장소에는 고객 시안·고객 자료를 올리지 마세요(PAGES-SETUP 참고)
- [ ] 샘플 화면 하단의 "본 페이지는 Project1 제작 샘플이며 가상의 업체입니다" 문구가 보이는지 확인
- [ ] 크몽 포트폴리오/이미지 칸에 샘플 캡처 업로드. 설명에 "가상 업체 시연용 샘플"이라고 적기. 실제 의뢰 실적처럼 보이게 하지 않기

## 4. 서비스 A 등록 (`kmong-product-A.md`)
- [ ] 새 서비스 등록 시작, 카테고리: 랜딩페이지 제작 계열 선택 (정확한 이름은 화면에서 선택)
- [ ] 제목 칸 ← [1] 서비스 제목
- [ ] 요약/한 줄 소개 칸 ← [2]
- [ ] 서비스 설명 칸 ← [3]
- [ ] 가격 설정: [4] 표 기준. 패키지 이름, 설명, 가격, 작업 기간 3일, 수정 횟수 1회 입력 (패키지 3단계가 필수인 화면이면 STANDARD만 채우고 나머지는 비활성/추가 옵션으로 처리하거나 화면을 알려 주세요)
- [ ] 서비스 제공 절차/기간 안내 칸 ← [5]
- [ ] FAQ 칸 ← [6] (Q/A를 하나씩 나눠 입력하는 화면이면 Q와 A를 분리해 붙여넣기)
- [ ] 의뢰인 요청사항(주문 시 입력 안내) 칸 ← [7]
- [ ] 태그 칸 ← [8] (쉼표 기준으로 하나씩)
- [ ] 대표 이미지 업로드 (샘플 캡처)
- [ ] 미리보기로 `{{ }}` 같은 미완성 표시, 오탈자, "[대표 확정]" 메모가 붙지 않았는지 확인
- [ ] 제출(검수 요청)

## 5. 서비스 B 등록 (`kmong-product-B.md`)
- [ ] 위 4번과 같은 순서로 B 문서의 [1]~[8] 입력
- [ ] 작업 기간 5일, 수정 2회, 가격 300,000원(대표 확정 후 값) 확인
- [ ] 추가 옵션 칸: 금액은 대표가 정할 때만 입력, 정하지 않으면 비워 두기 (문서에 숫자 없음)
- [ ] 병·의원 설명 중 의료광고 관련 안내 문구가 그대로 있는지 확인
- [ ] 제출(검수 요청)

## 6. 제출 후
- [ ] 검토 3~5영업일 대기. 반려되면 사유를 에이전트에 전달 (문구 수정)
- [ ] 공개되면 서비스 링크를 에이전트에 전달 (STATE.md 갱신)
- [ ] `intake-questionnaire.md` 와 `reply-templates.md` 는 의뢰/문의가 올 때 사용 (아래 7번)

## 7. 문의·주문이 오면
- [ ] 에이전트(p1-sales)가 `reply-templates.md` 기반 답변 초안 작성 → 대표가 확인 후 크몽 메시지로 직접 전송 (에이전트는 외부 발송 안 함)
- [ ] 주문 확인 후 `intake-questionnaire.md` 의 "붙여넣기" 부분 전송 (상품 A는 [B 전용] 항목 삭제)
- [ ] 질문지 답변 받은 날을 기록해 납기 계산
- [ ] 개인정보 폼 "예", 병·의원 업종이면 p1-qa 확인
- [ ] 납품은 `reply-templates.md` 6번, 구매 확정 후 후기 요청은 7번 (대표 승인 후 발송)
- [ ] 매출 발생 시: 구매 확정 후 출금 신청, 입금 확인, p1-cfo가 `finance/ledger.csv` 기록
